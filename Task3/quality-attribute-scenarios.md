# Quality Attribute Scenarios — Africa Delivery

**Status:** test design, not production test report. Six fields per scenario: source, stimulus, environment, artifact, response, measure. Baseline: Task2 modular monolith; two-country pilot **subject to legal sign-off**. Targets are provisional pending capacity measurement.

| ID / attribute | Stimulus source | Stimulus | Environment | Artifact | Expected response | Measurable response / acceptance |
|---|---|---|---|---|---|---|
| QAS-01 availability catalog | Buyer / synthetic probe | App container dies mid-request | 100 catalog RPS, single replica failure, normal service | LB, app, CDN/catalog | Healthy replica answers, stale public catalog allowed | ≥99.9% 30d good response SLI, failover symptom ≤60s in drill; no stale prices at checkout |
| QAS-02 availability PSP | PSP / external network | PSP timeout, 5xx, delayed webhook | 10 checkout RPS, partner outage 15 min | Order/Payment adapter, outbox | Circuit opens, persist pending, webhook reconciles; no fake paid | 0 duplicate financial effects after 100k replay; timeout ≤3s for internal intent; unsettled alerts after 15min |
| QAS-03 P99 latency | Synthetic 3G user | 2× peak requests and 3G throttling | k6 load + low-end Android lab | Catalog API + CDN | Cache hits / resize image / backpressure | API p99 ≤1s at 100 catalog RPS baseline; p75 first product ≤2s only **experimental** |
| QAS-04 throughput | Campaign traffic | Surge in catalog reads / orders | 100 catalog +10 checkout sustained RPS, 30min and 2× 5min | LB, pool, DB, queue | Scale stateless app, load shedding safely | ≥99% successful catalog responses baseline; order intent ≥99.9%, DB pool no exhaustion; peak RPS annotated |
| QAS-05 recovery RTO/RPO | Cloud node/storage failure | Kill primary DB / corrupt staging replica | Restore rehearsal, full backups + PITR (jurisdiction approved) | DB, backup, order data | Isolate, restore to last consistent recovery point, reconcile PSP | RTO≤60min, measured DB RPO≤15min; audit financial gaps; any missing matched PSP event blocks resumption |
| QAS-06 PII isolation | Malicious/misconfigured export | NG PII sent to unapproved KE/EU sink | Pen-test + migration dry run | Egress, logs, analytics, backup | Deny and log, flag Security+Legal | 0 unauthorised cross-border transfers; block test fixtures for each country |
| QAS-07 mobile reliability | Unstable mobile network | Client times out after checkout submit, retries | 3G loss/reorder 5%, PSP callback delayed | API order idempotency | Same order ID returned, no duplicate charge | 100k retry/replay tests, 0 duplicate confirmed payment effects |
| QAS-08 notifications degradation | SMS/WA vendor | Vendor 429/503 for 30min | Live queue simulator | Outbox + provider adapters | Bulkhead + exponential retry, do not affect checkout | Checkout intent SLI unaffected; alert queue lag >10min, messages never to unconsented recipients |
| QAS-09 portability | Ops / cloud migration | Switch approved provider/region | staging only, signed OCI images | IaC, app, DB migrations | Recreate environment and restore (subject to data law) | clean deploy ≤30min, no hardwired K8s or cloud-specific SDK in domain code |
| QAS-10 observability | On-call | Inject 5xx latency, saturation spikes | Staging with synthetic load | Telemetry pipeline | Alert with runbook and correlated trace | Rule fires ≤5min, essential golden-signal coverage, no PII in logs |

**Testing:** k6, Playwright mobile network emulation + real device spot check, PSP/webhook mocks, Toxiproxy network faults, backup restore exercise. Neither QAS nor proposed SLO signifies passed acceptance; record results/owners after tests. Related [NFR](nfr-registry.md), [FMEA](fmea.md), [Observability](observability.md).
