# Матрица соответствия требований Africa Delivery

**Дата аудита:** 2026-10-16  
**Область:** [описание проектной работы](https://github.com/dvtar91/Africa_Delivery/blob/main/description.md), [входные материалы](https://github.com/dvtar91/Africa_Delivery/tree/main/input_data), Task1–Task5 и шаблоны.  
**Назначение:** связывать расхождения с источниками, требованиями, рекомендуемыми решениями и ответственными.

> **Правило интерпретации.** Реальные противоречия между заинтересованными сторонами **не следует стирать из исходных писем**: они являются входом в архитектурный анализ. Рекомендуемые ниже меры — проектные предложения, не утверждённые решения. Документационные ошибки исправляются отдельно. Регуляторные тезисы исходных писем — предварительные; необходима проверка локальными юристами.
>
> **Приоритет:** P0 — блокирует безопасный/реалистичный запуск; P1 — существенно влияет на архитектуру и roadmap; P2 — исправление документации. **Тип:** конфликт требований, ошибка документации, пробел или ограничение реализации.

## Правила принятия решения

1. **P0:** CEO/инвестор утверждают бизнес-обязательство; CFO — финансовые лимиты; местные юристы/комплаенс подтверждают легальность; CTO/архитектор оформляют исполнимый вариант с измеримыми NFR.
2. **Трассировка:** каждый итоговый ADR должен ссылаться на IDs этой таблицы и первичные входные документы. Для решения указать `status = proposed / approved / rejected / deferred`, владельца и дату.
3. **Источники:** отсылки к бинарным приложениям [TCO XLSX](https://github.com/dvtar91/Africa_Delivery/blob/main/input_data/attachments/TCO_model_Africa_Delivery_template.xlsx) и [CN check-list DOCX](https://github.com/dvtar91/Africa_Delivery/blob/main/input_data/attachments/CN_check-list.docx) приводятся дополнительно к текстовым письмам. Для бюджета исходной истиной остаётся явное письмо CFO. Чек-лист CN — набор внутренних критериев, не доказательство внешней сертификации.
4. **Обновление:** после утверждения ADR-001–004 и юридических заключений обновлять статус строк, не редактируя исторические письма.
5. **Проверка полноты:** по каждой P0 строке необходимы подписанный owner decision, критерий приёмки и способ проверки (TCO, тест нагрузки, юридическое заключение, PSP договор или release go/no-go).
